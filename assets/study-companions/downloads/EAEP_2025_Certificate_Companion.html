Architecture in one glance

Client → HTTPS Web Adaptor → Portal for ArcGIS ↔ federated hosting GIS Server ↔ relational/object ArcGIS Data Store. The hosting server can additionally access registered external databases, folders and cloud stores. Public service URLs, direct admin URLs and storage connections fulfill different functions; do not conflate them.

Base architecture & network URLs

Portal manages identity, content and the organization; federated GIS Server executes services; ArcGIS Data Store provides managed storage; Web Adaptors offer front-door URLs.

Must-know patterns & exam decisions

A base deployment has Portal + hosting ArcGIS GIS Server + relational and object ArcGIS Data Stores + two Web Adaptors. Portal 7443, Server 6443, Data Store 2443 are direct component interfaces; clients normally use HTTPS Web Adaptor URLs.

ESRI READING Base deployment: installation tutorial ↗Configure federated server roles ↗ArcGIS Data Store types and layer uses ↗ArcGIS Enterprise WebGISDR backups ↗

Federation and hosting

Federation delegates server access control to the portal; the hosting server is the special federated GIS Server for hosted services.

Must-know patterns & exam decisions

Federation requires reachable services and admin URLs; admin URL must bypass web-tier auth. Hosting needs GIS Server Standard/Advanced plus relational data store; do not equate federation with hosting.

ESRI READING Configure federated server roles ↗Common problems and solutions ↗Base deployment: installation tutorial ↗

Authentication and secure exposure

Choose portal-tier/web-tier sign-in and apply least privilege with TLS, certificates and restricted anonymous access.

Must-know patterns & exam decisions

IWA uses IIS Web Adaptor; LDAP web-tier uses Java Web Adaptor. Portal-tier AD/LDAP allows built-in and organization logins but not automatic SSO. SAML is a separate IdP option. Restrict proxy capability and trust CA chains.

ESRI READING Portal authentication configuration ↗Security best practices ↗

Licensing and user types

Portal licenses user types, add-ons and extensions; ArcGIS Server requires separate machine authorizations and server roles.

Must-know patterns & exam decisions

Portal license JSON from My Esri replaces rather than merges existing allocations; include an admin-capable user type. Each ArcGIS Server machine needs proper authorization matching site edition.

ESRI READING Obtain a portal license file ↗Authorize ArcGIS Server ↗Manage portal members and user types ↗

ArcGIS Data Store storage choices

Select Esri-managed data stores by the actual hosted layer or workload, not by familiar DB names.

Must-know patterns & exam decisions

Relational stores hosted feature geometries; object supports query response caching, hosted 3D tiles, video, new 11.4 scene caches; tile cache holds legacy scene caches; graph and spatiotemporal serve specialized uses.

ESRI READING ArcGIS Data Store types and layer uses ↗ArcGIS Data Store vocabulary ↗ArcGIS Data Store deployment modes ↗

Server roles and utility services

Additional federated server roles expand capabilities beyond core hosting; organization utility service URLs power common applications.

Must-know patterns & exam decisions

Image Server for raster analytics/imagery, Notebook for notebook execution, Workflow Manager for workflows. Print/geometry services are stopped by default in relevant setups. Check server licensing and prerequisites before designating a role.

ESRI READING Configure federated server roles ↗ArcGIS Image Server raster analytics deployment ↗Configure utility services ↗Notebook Server 11.4 system requirements ↗Introduction to GeoEvent Server 11.4 ↗

Automated deployment choices

Choose the deployment approach according to topology, platform and repeatability requirements.

Must-know patterns & exam decisions

Builder is single-machine only and Windows Builder uses IIS with common install account/paths; PowerShell DSC and Chef support repeatable complex designs; cloud tools target AWS/Azure.

WebGISDR coverage and restore

WebGISDR backs up organization state but does not replace backups for data held outside the deployment.

Must-know patterns & exam decisions

Deploy ArcGIS Enterprise

26 questions
Q01What four logical software roles make up an ArcGIS Enterprise 11.4 base deployment, and what storage is mandatory?⌄

Answer: Portal for ArcGIS (organization, identity, content); ArcGIS GIS Server designated hosting server; ArcGIS Data Store with relational and object stores; and two ArcGIS Web Adaptors, one for Portal and one for Server. These can be collocated for a small deployment but fulfill distinct roles.

ESRI READING Base deployment: installation tutorial ↗ArcGIS Data Store types and layer uses ↗
Q02Which URLs should clients use, and which direct ports are pertinent to internal administration?⌄

Answer: Clients normally use the HTTPS organization and service URLs via Web Adaptor. Portal direct HTTPS uses 7443; ArcGIS Server administration uses 6443; ArcGIS Data Store web server uses 2443 for internal operations such as backup. Do not treat these as blanket internet-facing ports.

ESRI READING Base deployment: installation tutorial ↗ArcGIS Enterprise WebGISDR backups ↗
Q03How do federation and hosting-server designation differ?⌄

Answer: Federation registers a server with the portal and shifts security to the portal identity store. Designating a qualified federated ArcGIS GIS Server site as hosting server enables hosted layer publication and associated workflows. Federated alone does not mean hosting.

ESRI READING Configure federated server roles ↗Common problems and solutions ↗
Q04What licenses and ArcGIS Data Store prerequisite are required for a hosting server?⌄

Answer: Use an ArcGIS GIS Server site licensed Standard or Advanced and configure its relational data store before assigning the hosting role; a complete 11.4 base deployment also includes an object store.

ESRI READING Configure federated server roles ↗Base deployment: installation tutorial ↗
Q05Which administration URL should be used during federation with web-tier authentication?⌄

Answer: Use an ArcGIS Server administration URL reachable by the portal without web-tier authentication, normally HTTPS directly through port 6443. The services URL is the client-facing URL and is a separate setting.

ESRI READING Base deployment: installation tutorial ↗Common problems and solutions ↗
Q06What happens to ArcGIS Server security after federation?⌄

Answer: Portal accounts and their privileges govern the federated server. The primary site administrator remains a limited direct Administrator Directory recovery path through the direct server port; it is not the normal login to Server Manager after federation.

ESRI READING Common problems and solutions ↗
Q07When is IIS ArcGIS Web Adaptor required for Windows single-sign-on?⌄

Answer: When using integrated Windows authentication for Windows Active Directory at the web tier. For LDAP web-tier authentication, ArcGIS Web Adaptor is deployed on a supported Java application server instead.

ESRI READING Portal authentication configuration ↗
Q08Why does portal-tier Active Directory authentication not equal IWA single-sign-on?⌄

Answer: Portal-tier AD/LDAP accepts both built-in and organization-specific credentials through the portal sign-in; users re-enter organization credentials. IWA single-sign-on is a web-tier configuration using IIS.

ESRI READING Portal authentication configuration ↗
Q09How do you mitigate a portal proxy SSRF risk according to Esri security guidance?⌄

Answer: Restrict the portal's proxy capability to approved web addresses, along with HTTPS, trusted CA-signed certificates, tight anonymous-access policy, and controlled administrative exposure.

ESRI READING Security best practices ↗
Q10What two settings may need change to actually disable anonymous use when using web-tier authentication?⌄

Answer: Disable anonymous access in the portal organization and at the web server when web-tier authentication is configured. Portal item/service sharing permissions still independently control underlying resources.

ESRI READING Security best practices ↗
Q11How is Portal for ArcGIS 11.4 licensed, and what is the replacement risk?⌄

Answer: Use the My Esri-generated portal .json containing user types, extensions and add-on apps, including an administrator-compatible type. Importing a new file overwrites previously licensed allocations; omitted app/user-type licenses disappear.

ESRI READING Obtain a portal license file ↗
Q12How is ArcGIS Server authorized across a multimachine site?⌄

Answer: Each ArcGIS Server machine requires a valid authorization file and the same server license edition across the site. Match the intended licensing role and reauthorize as required during upgrade.

ESRI READING Authorize ArcGIS Server ↗
Q13Where are hosted feature geometry and attributes stored, compared with hosted feature query response caches?⌄

Answer: Relational ArcGIS Data Store holds hosted feature geometries, attributes and attachments. Object store can hold cached results for specified hosted feature-layer sublayer queries; it is not the primary hosted feature data repository.

ESRI READING ArcGIS Data Store types and layer uses ↗
Q14What changed for new hosted scene-layer cache storage in ArcGIS Enterprise 11.4?⌄

Answer: Newly published hosted scene-layer caches use the object store; preexisting scene caches in a tile cache data store remain there until they are migrated.

ESRI READING ArcGIS Data Store vocabulary ↗ArcGIS Data Store types and layer uses ↗
Q15Which store is required for hosted 3D tile layers, and which for hosted spatiotemporal feature layers?⌄

Answer: Object store supports hosted 3D tile caches. Spatiotemporal big data store supports hosted spatiotemporal feature layers; the latter is a specialized store beyond core base deployment operation.

ESRI READING ArcGIS Data Store types and layer uses ↗
Q16What are the relational store’s deployment mode and object-store mode options in 11.4?⌄

Answer: Relational supports primary-standby with one or two machines. Object store uses single-instance or cluster deployment; clustered 11.4 object store requires three or more machines, in an odd number. High-availability installation itself is outside the exam's stated tasks.

Q17Why should a raster-analysis requirement not be assigned to an ordinary GIS Server hosting role?⌄

Answer: Distributed raster analysis is an ArcGIS Image Server role. Image hosting can be combined with raster analysis on a suitable Image Server or separated to isolate processing from delivery.

ESRI READING ArcGIS Image Server raster analytics deployment ↗Configure federated server roles ↗
Q18Which role runs portal notebooks and what is a prerequisite?⌄

Answer: Federate an appropriately licensed ArcGIS Notebook Server site and assign notebook server role; a portal hosting server must already be configured. Notebook Server executes in isolated container-based environments.

Q19What does Workflow Manager Server contribute and what is required before assigning it?⌄

Q20How is a custom geometry utility service typically enabled?⌄

Q21What is the printing utility service nuance for a base deployment?⌄

Q22When is ArcGIS Enterprise Builder unsuitable?⌄

Q25Which identity function belongs to user type versus member role?⌄

Answer: User type determines available apps, capabilities and license entitlements; roles define which administrative/publishing/editing privileges a member can exercise within that entitlement. Both must be appropriate.

Q57When is a hosted feature layer different from a referenced feature layer?⌄

Answer: Hosted feature publication copies source data to the hosting server's managed relational store. Referenced data remains in an administrator-registered enterprise database and is published through a federated ArcGIS Server, often alongside a dependent map image layer.

ESRI READING Service publishing in ArcGIS Pro ↗
Q58What is the purpose of a map image layer when publishing registered enterprise data?⌄

Answer: It exposes map rendering through a map service that references source datasets, with optional dependent feature access for editable/queryable feature layers where supported.

ESRI READING Service publishing in ArcGIS Pro ↗Edit map service capabilities ↗
Q59Which map service capabilities expose OGC map imagery versus vector feature geometry?⌄

Answer: WMS exposes rendered map images; WFS provides vector feature geometry. Feature Access exposes an ArcGIS feature service and requires vector layers.

ESRI READING Edit map service capabilities ↗WMS services ↗
Q60Can a shared-instance map service expose arbitrary optional capabilities?⌄

Answer: No. The supported optional map service capabilities for shared instances are limited to Feature Access, WFS, WMS and KML; other capabilities require dedicated operation.

Q61What does a portal data-store item register with the Enterprise organization?⌄

Answer: A user-maintained folder, database, or cloud-store connection for specified federated ArcGIS Server sites. Registration lets services reference the source; it does not upload its data into ArcGIS Data Store.

ESRI READING Add folder, database, or cloud data store item ↗
Q62What must be true for a registered folder/database to work in a multimachine federated site?⌄

Answer: Every server machine in that site must have necessary network access, drivers as appropriate and permissions/credentials for the registered data source.

ESRI READING Add folder, database, or cloud data store item ↗
Q63What special use does a cloud-storage data store item support?⌄

Answer: It can reference image files for imagery layer publication and precreated caches for 3D tiles, scene, tile or vector tile layers in a supported cloud provider location.

Q64Why might deleting a source shapefile break an existing hosted feature layer workflow?⌄

Answer: The hosted layer can remain accessible, but the source-file item dependency supports operations like overwrite; deleting it can prevent future overwrites.

Q65What should happen before deleting a primary hosted feature layer with views and WFS dependencies?⌄

Answer: Delete dependent hosted layers/views first, then the source layer. Dependencies are shown by Created from, Published as and Other Views on layer item pages.

Q66What happens when a primary hosted feature layer is reassigned to another owner?⌄

Answer: Dependent hosted layers/views and the publication source file are reassigned with it, preserving co-ownership requirements. The new owner must satisfy applicable group-sharing eligibility.

Q67What conditions must be met when transferring an item shared to groups?⌄

Answer: The new owner must belong to every sharing group and have the group's required contribution privilege (including owner/manager restrictions); admins can use Manage items for transfer.

Q68What controls whether a member may publish, administer and access applications?⌄

Answer: User type sets entitled capabilities and applications; member role provides privileges; licensing allocations and group/resource sharing may impose additional requirements.

Q69What are shared-update groups intended to enable and what is the risk?⌄

Answer: They allow qualified members to update others' shared maps/app item contents and certain layers. Membership grants elevated edit/schema privileges; the setting must be chosen at group creation.

Q70Why isn't a regular shared group the same as a distributed collaboration workspace?⌄

Answer: Groups manage sharing within an organization; distributed collaboration establishes participant organizations and workspaces tied to participating groups with rules for shared items and synchronization.

Q71How are feature layers shared by reference in distributed collaboration?⌄

Answer: The recipient gets an item pointing to the original service; data stays at the source and users need public access, saved credentials or permitted origin-organization authentication.

Q72What is needed before sharing eligible feature layers as copies?⌄

Answer: Enable sync on eligible source feature layers and configure a collaboration workspace to send copies. Guest participants control the schedule for synchronization.

Q73What happens if a layer does not support copy-based synchronization?⌄

Answer: Depending on workspace fallback configuration, it is shared as a reference or excluded instead; declaring a workspace copy policy does not make an incompatible service syncable.

Q74Who schedules distributed collaboration synchronization and who may manually synchronize on demand?⌄

Answer: Guest ArcGIS Enterprise participants set workspace schedules; on-demand synchronization is supported for authorized guest Enterprise administrators, not the collaboration host.

Q75What concurrency nuance applies to two-way edit sync in distributed collaboration?⌄

Answer: There is no automatic conflict detection/prevention for simultaneous edits; last submitted change wins. Govern edit ownership/processes and consult archived history to resolve conflicts.

PART 04 · BLIND SPOTS

The details people often overlook

These are 20 documentation-backed distinctions likely to create mistakes in a real-world administration scenario. They are derived from Esri's published behaviors—not claimed statistics about past candidates or undisclosed exam questions.

DEPLOY01

Version drift: 11.4 object store is not optional in a fresh base pattern

Legacy tutorials often focus on relational + tile cache. At 11.4 newly published hosted scene caches, 3D tiles and some other data use the object store; legacy scene caches are a migration case.

ESRI READING ArcGIS Data Store types and layer uses ↗ArcGIS Data Store vocabulary ↗
DEPLOY02

Federated is not the same thing as hosting

A perfectly healthy federated Server site does not automatically host feature layers. Verify Standard/Advanced GIS Server license, relational store and specific designation.

ESRI READING Configure federated server roles ↗
DEPLOY03

Don’t confuse Esri-managed storage with user-registered storage

Managed ArcGIS Data Store serves hosted data; registered database/folder/cloud items point to externally maintained sources. This changes security, publishing behavior and backups.

ESRI READING ArcGIS Data Store types and layer uses ↗Add folder, database, or cloud data store item ↗
DEPLOY04

Portal-tier AD is not IWA SSO

The presence of AD users alone does not enable automatic login. Determine whether the design needs IIS web-tier IWA, portal-tier organization accounts, or SAML.

ESRI READING Portal authentication configuration ↗
DEPLOY05

Portal license import is a replacement, not merge

Export/check existing allocations, all app and extension entitlements, the organization URL, and administrator-compatible user types before importing new JSON.

ESRI READING Obtain a portal license file ↗
DEPLOY06

Builder limitations are often more important than its convenience

Single machine, IIS on Windows, common paths/service accounts, and no DNS alias. The scenario is usually asking Builder versus Chef/PowerShell DSC.

ESRI READING ArcGIS Enterprise Builder limitations ↗Esri Enterprise deployment tools ↗
DEPLOY07

Server roles: know what a role does without implementing the workflow

Image Server for raster analysis/imagery, Notebook Server for notebooks, GeoEvent for streams, Workflow Manager for workflows. Installing these or running analyses is outside blueprint scope.

ESRI READING Configure federated server roles ↗ArcGIS Image Server raster analytics deployment ↗Notebook Server 11.4 system requirements ↗Introduction to GeoEvent Server 11.4 ↗
TROUBLESHOOT08

Capture a request ID before restarting anything

Portal log query can include federated Server and Data Store; timestamp alone can be ambiguous on a busy site. Reproduce at suitable log level, correlate, and revert verbose logs.

ESRI READING Work with portal / organization logs ↗
TROUBLESHOOT09

SSL trust and wrong federation URLs resemble service outages

Always distinguish public service URL from direct administration URL, and check CA chain, reverse proxy, IWA and back-end reachability before changing privileges.

ESRI READING Configure federated server roles ↗Common problems and solutions ↗Configure utility services ↗
TROUBLESHOOT10

No one performance metric proves the cause

High response times may originate in instance starvation, request spikes, source database I/O or processing. Correlate Server request/timeouts/instances with host resource usage.

MAINTAIN11

WebGISDR does not protect referenced database contents

A successful archive is not evidence that DBMS rows, files and cache directories are recoverable. Document every excluded dependency and perform restore rehearsals.

MAINTAIN12

Backup, Full and Incremental are different WebGISDR modes

A single full-mode backup is not the same operational schedule as ordinary Backup mode. Incremental has point-in-time and relational-backup prerequisites.

ESRI READING ArcGIS Enterprise WebGISDR backups ↗
MAINTAIN13

Restores have matching-version and URL constraints

The restore target may use different machine names but must meet same OS type, component versions, public organization/service URLs and datastore requirements.

ESRI READING ArcGIS Enterprise WebGISDR backups ↗Restore ArcGIS Enterprise ↗
MAINTAIN14

Service pooling is capability-limited

Only eligible map/image services; GP services cannot share the pool. Dedicated is valuable for SLA/compute-heavy work. New-site defaults and upgraded-site defaults can differ.

ESRI READING Configure shared and dedicated service instances ↗
MAINTAIN15

A valid upgrade plan includes Web Adaptors and licensing

It is not enough to upgrade Portal and Server binaries. Follow the documented order; refresh authorizations; test critical service and hosted layer paths after.

ESRI READING Upgrade Portal for ArcGIS / upgrade order ↗Upgrade ArcGIS Data Store ↗
MANAGE16

Dependent hosted layers block source deletion

Views, hosted WFS and some derivative tiles are part of a dependency graph. Inspect Created from / Published as / Other Views; delete dependents first.

ESRI READING Hosted layers and dependencies ↗
MANAGE17

A shared-update group gives more power than the label suggests

This can include edits/schema and attachment configuration; membership is a privileged design choice, not a casual collaboration setting.

ESRI READING Create groups and shared-update groups ↗
MANAGE18

Reference and copy collaboration produce different data and security behavior

References require original-source access; copies transfer eligible feature data with sync. Unsupported sync may fall back to reference or no sharing.

MANAGE19

Only guests control scheduled or on-demand workspace sync

Don’t assume an Enterprise collaboration host can synchronize on demand; workspaces and synchronization are controlled by participating Enterprise guests.

Two-way edits are not conflict-free

Last submitted edit wins; avoid concurrent ownership and consider archived history when reconciling collisions.
